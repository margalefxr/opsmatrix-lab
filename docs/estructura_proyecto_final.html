0. Contexto de Negocio y Marco Normativo

Propósito de la Infraestructura (OpsMatrix)
  • Caso de Uso Industrial: Simulación de la plataforma central de procesamiento de datos transaccionales para una entidad fintech o proveedor de servicios críticos en Europa.
  • Cumplimiento GRC: Alineación estricta con el marco normativo ISO/IEC 27001:2022 (gestión de accesos, cifrado en tránsito y control de secretos).
  • Gobierno y Trazabilidad ("Docs as Code"): Decisiones arquitectónicas registradas mediante Architecture Decision Records (ADRs) y control forense con conventional commits.

1. Principios de Diseño y Entorno Bare-Metal

Principios Operativos (Zero Trust)
  • Aislamiento de Red: Segmentación estricta entre redes públicas (frontend) y privadas (backend aisladas).
  • Cifrado Fuerte: Terminación perimetral exclusiva mediante TLS 1.3 y PKI interna.
  • Observabilidad Activa: Monitorización perimetral de red en tiempo real mediante Suricata IDS.
Stack de Infraestructura Base
  • Target Host / OS: Ubuntu Server (Bare-Metal / VM Homologada).
  • Orquestación: Docker Engine & Compose v2 (Arquitectura Modular de 3 Capas).
  • Seguridad Perimetral: Nginx Reverse Proxy | OpenSSL PKI | Suricata IDS.

2. Hoja de Ruta Operativa Paso a Paso

FASE 0: Aprovisionamiento Bare-Metal y Setup de Infraestructura
  • 0.1 Aprovisionamiento VM Target: Despliegue de nodo Ubuntu Server, configuración de red e interfaces físicas (enp2s0).
  • 0.2 Hardening SSH & Docker Setup: Acceso remoto seguro, despliegue de Docker Engine y asignación de permisos de grupo.
  • 0.3 Inicialización Git & Gobierno: Estructuración de directorios del proyecto, políticas de control de secretos (.gitignore estricto) y plantillas de entorno.
FASE 1: Detección, Observabilidad y Línea Base
  • 1.1 Suricata IDS en Perímetro: Configuración e integración de Suricata IDS como servicio systemd sobre la interfaz de red física.
  • 1.2 Centralización de Logs: Mapeo de evidencias de seguridad (logs de sistema, IDS y proxy).
  • 1.3 Baseline & Healthcheck: Scripts de control automatizado para la validación de la salud operativa del sistema.
FASE 2: Cifrado, PKI e Infraestructura HTTPS
  • 2.1 Despliegue PKI Local: Generación de Autoridad Certificadora (CA) raíz privada y emisión de certificados firmados para el dominio/IP corporativa.
  • 2.2 Nginx Reverse Proxy TLS 1.3: Configuración del proxy para redirección HTTP (80) → HTTPS (443) forzando exclusivamente protocolos TLS 1.3.
  • 2.3 Volúmenes y Montaje Seguro: Estructuración de volúmenes con rutas absolutas en Docker para garantizar la persistencia y aislamiento de claves.
FASE 3: Hardening, Aislamiento y Simulación de Servicios
  • 3.1 Segmentación de Redes Docker: Creación de redes dedicadas y aislamiento de la base de datos MariaDB (internal: true) frente a accesos directos externos.
  • 3.2 Orquestación del Stack: Despliegue automatizado de servicios web y base de datos con persistencia segregada.
FASE 4: Auditoría Cruzada, DFIR y Reporte Ejecutivo
  • 4.1 Auditoría Técnica y Defensa: Verificación de puertos en escucha, análisis de logs de IDS y comprobación de políticas de cumplimiento ISO 27001.
  • 4.2 Presentación Ejecutiva: Demostración de resiliencia operativa y robustez arquitectónica ante comités técnicos y evaluación docente.
